Agente de IA para Instagram

Agente conversacional desenvolvido para automatizar o atendimento e apoiar a qualificação de leads originados no Instagram, conectando automação, API REST e inteligência artificial generativa em um fluxo seguro e contextual.

01

O problema

Negócios que utilizam o Instagram como canal de aquisição podem receber perguntas repetitivas, solicitações fora do horário de atendimento e contatos de potenciais clientes em diferentes estágios de interesse.

Quando todo o atendimento depende de intervenção manual, o tempo de resposta aumenta e oportunidades comerciais podem ser perdidas.

Desafio central Automatizar parte da conversa sem limitar o atendimento a respostas fixas e sem misturar o contexto entre diferentes usuários.

02

A solução

O projeto utiliza uma API desenvolvida em Flask para conectar o fluxo de automação ao Google Gemini.

Cada mensagem recebida é associada ao identificador do usuário, processada pelo agente e enviada ao modelo de inteligência artificial juntamente com o contexto correspondente daquela conversa.

Atendimento contextual

O agente utiliza o histórico da conversa para produzir respostas coerentes com as interações anteriores.

Qualificação

A conversa é estruturada para compreender necessidades e identificar oportunidades comerciais.

API REST

Uma API Flask recebe as mensagens da camada de automação e centraliza o processamento do agente.

Prompt Engineering

Persona, regras de atendimento, jornada de conversa e contexto comercial são definidos de forma estruturada.

03

Arquitetura

A solução foi dividida em camadas para evitar que integração, regras do agente, memória conversacional e configuração permanecessem concentradas em um único arquivo.

Instagram

Canal de origem das interações dos potenciais clientes.

Make.com

Atua como camada de automação e orquestração das mensagens.

Flask REST API

Recebe e valida as requisições, controla o acesso e encaminha o processamento.

Agent Service

Concentra a lógica responsável pela interação entre contexto, prompt e modelo de IA.

Memória

Mantém o contexto separado por identificador de usuário.

Google Gemini

Modelo responsável pela geração das respostas em linguagem natural.

Fluxo principal Instagram → Make.com → Flask REST API → memória da conversa → Agent Service → Google Gemini → resposta.

04

Memória por usuário

Um dos pontos críticos durante a evolução do projeto foi o isolamento do histórico conversacional.

A implementação inicial utilizava uma única estrutura de histórico. Em uma aplicação com múltiplos usuários, essa abordagem poderia causar compartilhamento de contexto entre conversas diferentes.

Solução adotada Cada conversa passou a ser identificada por um user_id, mantendo históricos independentes para cada usuário.

Essa mudança aumentou a segurança, a previsibilidade das respostas e a consistência do contexto enviado ao modelo.

05

Segurança da API

A API recebeu controles para reduzir requisições inválidas, exposição de informações internas e utilização indevida do serviço.

API Key

O acesso ao endpoint protegido depende de uma chave configurada por variável de ambiente.

Validação

Campos obrigatórios e conteúdo das requisições são verificados antes do processamento.

Rate limiting

Limites de requisição ajudam a proteger o serviço contra abuso e consumo excessivo da API de IA.

Erros controlados

Exceções internas não são retornadas diretamente para o usuário da API.

06

Resiliência

Integrações com modelos externos podem apresentar indisponibilidade temporária, limites de uso ou falhas de comunicação.

O agente possui tratamento de erros, estratégia de retry e mensagens de fallback, evitando que uma falha técnica seja exposta diretamente ao usuário.

  • tratamento de indisponibilidade do Gemini;
  • novas tentativas controladas;
  • respostas de fallback;
  • endpoint de health check;
  • logging das ocorrências internas.

07

Qualidade e testes

O projeto possui testes automatizados utilizando Pytest para validar os principais comportamentos da API sem depender de chamadas reais ao serviço do Gemini durante a suíte.

  • health check;
  • autenticação da API;
  • validação de payload;
  • campos obrigatórios;
  • fluxo de requisição válida;
  • isolamento entre usuários;
  • comportamento diante de falhas externas.
Qualidade de código Pytest é utilizado nos testes automatizados e Ruff auxilia na padronização e análise estática do código Python.

08

Docker e CI

O ambiente da aplicação pode ser reproduzido por container, reduzindo diferenças entre desenvolvimento e execução.

Docker

Containerização da API e de suas dependências para execução padronizada.

Gunicorn

Servidor WSGI utilizado para execução da aplicação em ambiente de produção.

GitHub Actions

Pipeline automatizado para validação do projeto no repositório.

Ruff + Pytest

Verificação da qualidade do código e execução automatizada dos testes.

09

Decisões de engenharia

Flask em vez de uma arquitetura maior O escopo da aplicação não exigia um framework mais complexo. Flask mantém a API pequena, clara e adequada à responsabilidade do serviço.
Make.com como orquestrador A automação da plataforma social permanece desacoplada da lógica do agente, permitindo que a API Python se concentre em validação, contexto e inteligência artificial.
Arquitetura proporcional O código foi separado por responsabilidades sem introduzir camadas e abstrações que não agregariam valor ao tamanho atual da solução.

10

Limitações e evolução

A versão atual mantém a memória das conversas localmente no processo da aplicação.

Essa abordagem é suficiente para o estágio atual do projeto, porém não é indicada para múltiplas instâncias ou persistência de sessões em ambientes distribuídos.

Próxima evolução Utilizar Redis com TTL para armazenar sessões temporárias e permitir que diferentes instâncias da aplicação compartilhem o contexto das conversas.

Redis permanece como roadmap e não faz parte da implementação atual.

11

Resultado

O projeto evoluiu de um protótipo simples de integração com inteligência artificial para uma API estruturada, testada e preparada para operar como componente de um fluxo automatizado de atendimento.

  • atendimento baseado em linguagem natural;
  • contexto isolado por usuário;
  • qualificação de potenciais clientes;
  • integração desacoplada via API REST;
  • controles básicos de segurança;
  • testes automatizados;
  • execução containerizada;
  • pipeline de integração contínua.
